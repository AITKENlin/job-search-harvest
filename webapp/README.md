# 40+ 求职建议 · 网页互动版（job-search-harvest / webapp）

> **地区中立**：本工具**不绑定任何城市**。检索地区由**你自己输入的需求**决定——
> 想找上海就写「上海 品牌经理」，想找成都就写「成都 品牌内容」。
> 也可用环境变量指定默认城市：`JOB_CITY=上海 python app.py`。
> 内置的 `positions.json` 只是**样本数据集**（示例城市见其 `meta.sample_city`），换城市替换该文件即可。

## 这是什么

一个**本地运行**的网页工具：上传简历 → 解析 → 填简短问卷 → 输出求职建议。专为 **40+ 求职者**设计，内核是第一性原理：

> **收入不要断 ＞ 专业对口 ＞ 薪资预期 ＞ 城市就近**

职位库以**外企 / 合资为主**——外企 HC 多走全球 EVP，社招普遍看"经验 + 专业能力"而非年龄，且不少岗支持远程 / 异地 base，是 40+ 人群更友好的赛道。

## 第一性原理（贯穿所有建议）

- **收入不要断**：优先"能最快入职"的岗，薪资可先放低（先续上现金流，再谋升级）。
- **不苛求专业对口**：从经历中找可迁移职能（沟通 / 文案 / 培训 / 项目管理）投递。
- **地点不限于本地**：可远程、可外地 base、可出差型岗都纳入考虑。
- **外企 / 合资优先**：年龄歧视低、看能力。
- **过渡组合**：顾问 / 兼职 / 项目制 + 政策现金流（失业金 / 灵活就业补贴）保底。

## 功能

- **激励首屏 + 激励段落**：首页给出「年龄是筛选函数，不是劣势函数」的开场；分析结果第一块是「写在你打开岗位列表之前」，由 `analyzer.py::_encourage()` 按用户真实履历（年龄 / 年资 / 技能 / 约束）动态生成，**不空喊口号、不承诺结果**。
- 简历解析：PDF / DOCX / TXT（也可直接在文本框粘贴文字）。
- 简历体检：优势 / 缺口 / 年龄风险点。
- 求职策略：基于第一性原理。
- Top N 推荐岗：外企优先标注、薪资、可否远程/外地、年龄友好、匹配理由、来源。
- 大厂 HR 2026 最新需求 · 能力对标。
- **实时搜索**：结果以表格呈现，每行给出**公司名字 / 公司属性 / 地区 / 职位名称 / 直链网址 / 投简历的邮箱**；人社官方 + 外企官网 + 主流平台三渠道，**零配置即可用**（见下节）。
- 可选 DeepSeek 增强：设 `DEEPSEEK_API_KEY` 后，模拟大厂 HR 给补充建议（投递话术 / 能力补齐 / 薪资底线）。

## 实时搜索：零配置即可用

**设计原则：帮到人 ＞ 功能强大。** 多一个配置项，就多一次放弃。所以本工具**不要求你申请任何 API key**——搜索能力来自**运行本工具的 AI 助手本身**（它自带联网搜索），你只要输入想找什么岗位。

**三个渠道**（页面上勾选，默认全选）：`人社`（人社/国企官方公告，**含报名邮箱**）· `外企`（外企/合资官网 careers）· `主流平台`（猎聘/BOSS/智联/51job 实时在招）。

### 搜索结果长什么样

**按你输入的关键词检索并排序**（搜"品牌"就出品牌岗，搜"会计"就出财务岗），每行直接给出求职要用的六件事 + 投递方式：

| 公司名字 | 公司属性 | 地区 | 职位名称 | 直链网址 | 投递邮箱 / 报名方式 |
|---|---|---|---|---|---|
| 广州星际悦动 usmile | 新锐消费品牌（个护） | 广州-天河 | 品牌内容经理 | 打开 → | 猎聘站内投递（点直链→在线沟通/投递） |
| 广州市越秀区光塔街街道办事处 | 政府机关（编外辅助岗） | 广州-越秀区 | 公共服务综合窗口前台辅助人员【即将开始报名】 | 打开 → | 仅现场报名（越秀区光塔路21号二楼） |
| 广州市越秀区发展和改革局 | 政府机关（编外合同制） | 广州-越秀区 | 行政辅助类合同制工作人员 | 打开 → | yxqfgjyxk@gz.gov.cn |

「渠道入口」（人社官网、外企 careers 目录）**单独折叠展示**，不会被混进岗位列表——它们不是岗位，只是进站找岗的入口。

### ⚠️ 关于「投递邮箱」的实话（含一处关键修正）

**邮箱只存在于「人社/国企官方公告」渠道，且并非每个公告都发邮箱。**

| 渠道 | 有公开投递邮箱吗 | 实测依据 |
|---|---|---|
| **人社/国企官方公告** | ⚠️ **部分有** | 有的写「发送至电子邮箱 xxx@xxx」；**也有不少改走在线报名系统或现场报名** |
| 主流平台（猎聘等） | ❌ 没有 | 正则扫全页，邮箱命中 **0** 条；平台走站内沟通 |
| 外企官网 | ❌ 基本没有 | 走 ATS 申请系统 |

**关键修正**：只给一列「邮箱」是不够的——渠道不发邮箱时，用户看到的是一个**空格**，等于毫无行动指引。因此现在的规则是：

1. **邮箱空着，比编造好**（不编造、不猜测）；
2. **但邮箱为空时必须给出「报名方式」**，写清真实投递路径（平台站内直投 / 官网系统 / 线上报名 / 现场报名）；
3. **验收标准：列表里不允许出现「投递方式为空」的行。**

想拿到带邮箱的岗位，就在「人社/国企官方公告」这个渠道搜索——或直接让 AI 助手去搜「广州+区名+事业单位/国企+招聘公告」。

**两条零配置路径**（程序自动择优，你无需选择）：

| 路径 | 说明 |
|---|---|
| `agent` | AI 助手搜完后把结果喂进来（写 `positions_live.json`，或 `POST /search/import`）。**零配置** |
| `direct` | 直连招聘网站抓取（人社官网目录 + 外企目录 + 猎聘 SEO 页）。**零配置**，即开即用 |

默认 `auto`：**有助手落盘结果就用 `agent`，否则用 `direct`**。两条都不需要 key；传非法后端名也不会报错，自动回落 `direct`。

### 接口

- `GET /search?q=广州 品牌内容&sources=人社,外企` → `{query, backend, sources, count, results[], channels[], channel_count, matched_terms, query_applied, email_count}`
  - `results` = **岗位**（已按 `q` 相关度过滤 + 排序）
  - `channels` = **渠道入口**（人社官网 / 外企 careers 目录），不是岗位
- `POST /search/import`，体 `{"results":[{company, role, city, salary, source, source_type, ...}]}` → 去重合并进 `positions_live.json`
- `GET /search/backends` → 各路径可用性（**不回传任何 key**）

### 检索是怎么工作的（2026-09-21 修复）

早期版本存在一个严重缺陷：**query 完全不参与检索**——`_liepin(query)` 收了关键词却从不使用（slug 写死），`harvested` 段从未被读取，且 19 条「渠道入口」占满结果名额。结果是**搜什么结果都一样、且几乎全是无邮箱的伪岗**。

现在的机制：

| 环节 | 做法 |
|---|---|
| 切词 | 按空白/标点切分 + 剔停用词 + **中文长词补 2-gram**（"品牌营销"→品牌/牌营/营销），解决中文无词边界问题 |
| 打分 | 字段权重：`role 4.0` > `company/company_type 2.0` > `duty 1.2` > `city 1.0` > `exp/edu 0.6` |
| 过滤排序 | 过滤零相关 → 按 `(相关度, 有邮箱, 年龄友好, 外企, 快速就业, 有直链)` 排序；**过滤后为空则退回全集**，绝不甩空列表 |
| slug 路由 | 关键词→slug 映射（品牌/内容/出海/咨询/培训/总监/市场/电商 八条线），无命中回落默认，上限 6 页控延迟 |
| 岗位/入口分离 | 入口走 `channels()` 单独返回，不占 `max_results` 名额 |

### 自行扩展后端

继承 `SearchBackend`，实现 `search(query, sources, max_results) -> List[dict]`，用 `_norm()` 归一化后注册进 `SearchEngine.backends`。前端与调度无需改动。

**实测基线**：`direct` 路径在受限网络下**可用**——猎聘 SEO 落地页 6 个 slug 全部 HTTP 200，去重后单页约 37 条唯一岗位（注意：页面无结构化 JSON，只有 HTML，且存在 class 重叠片段，必须去重）。

## 岗位库 `positions.json`

- `announcements`：**官方公告岗**（人社/国企/机关），已逐条核对原文，含**报名方式 / 报名截止日期 / 年龄要求 / 状态**。这是唯一能稳定提供「投递邮箱」的数据源。**注意：近来越秀区公告多改走「现场报名」或「线上报名系统」，邮箱为空但 `apply_method` 必填。**
- `harvested`：已核实真实岗，含 `company_type`（公开常识标注）、`link`（由 source 标注推导）、年龄友好、快速就业、远程/外地、档位。
- `mnc_directory`：外企/合资官网 careers 目录（仅公司名 + 官方链接 + 广州 presence），**不编造具体岗位与薪资**。

## 维护

- **新增外企**：往 `mnc_directory` 加 `{name, type, gz, careers_url, note}`。
- **新增公告岗**：核实原文后加进 `announcements`（含 `email` 或 `apply_method`、`deadline`、`status`、`age_friendly`、来源链接）。
- **新增真实岗**：官网 / 猎聘核实后加进 `harvested`（`source` 写 `liepin <slug>` 或 `liepin job/<id>`，链接会自动推导）。
- **扩采集面**：往 `search.py` 的 `SLUG_ROUTES` 加关键词→slug 映射即可，无需改其他代码。
- **外企官网直采方法**：见 skill `SKILL.md`「外企官网 careers 直采」一节（MNC directory + `site:` 检索 + RSS + 公众号 / LinkedIn）。

## 地区中立（换城市不用改代码）

**地区永远由用户输入决定**，工具不预设任何城市：

| 场景 | 行为 |
|---|---|
| `q="上海 品牌经理"` | 自动识别城市＝上海，抓上海的落地页、给上海的渠道入口 |
| `q="品牌经理"` + `&city=深圳` | 用显式指定的城市 |
| `q="品牌经理"`（没提城市） | 用 `JOB_CITY` 环境变量；没设则用样本城市兜底 |
| 未收录的城市（如"火星城"） | **不猜网址**：只给全国通用官方渠道（人社部·中国公共招聘网 / 12333），并给一句"用你的 AI 助手检索〈某某人社局 招聘公告〉"的自助提示 |

**要做的事**：
- 想支持新城市 → 往 `region.py` 的 `CITY_PARAMS` 加一行 `"城市名": "平台参数"`；
- 想补该城市的官方渠道 → 往 `CITY_OFFICIAL` 加（**须先核实真实存在**，不编造）；
- 想换样本岗位池 → 替换 `positions.json`，并把 `meta.sample_city` 改成新城市。

`region.py` 是唯一的地区真相来源；`search.py` / `app.py` / `analyzer.py` 都从它取城市，不各自写死。

## 通用化（面向所有 40+ 求职者，不锚定任何个人）

本工具**不锚定任何特定个人**。所有结论——简历体检、求职策略、Top 推荐、激励文案——都由**用户自己上传的简历 + 问卷**动态生成；换一个人用，结论就换成他的。

- 前端首屏的激励语是**通用表述**，不含任何真实个人姓名、公司或履历。
- `analyzer.py` 的评分与文案只使用「年龄 / 年资 / 技能 / 约束」四类**可复用变量**，不写死任何个人的专有信息。
- `positions.json` 是**样本岗位池**（示例城市见 `meta.sample_city`，当前为广州的内容/品牌/顾问/文宣线），仅用于演示排序逻辑与字段契约；换城市或换行业时替换该文件即可，`search.py` 与 `analyzer.py` 无需改动。
- 换城市要动的只有两处：`positions.json`（样本岗位池）+ `region.py`（城市参数与本地官渠）。`search.py` 的 `SLUG_ROUTES` 按**职能**划分、不绑城市，一般不用改。
- 分析结果里会**如实标注**推荐岗来自样本岗位池，并引导用户用实时搜索找自己城市的岗位——不假装样本数据就是用户所在城市的全量在招岗。

## 纪律

- 所有岗位 / 薪资须有来源，推断标"待核实"，禁止编造。
- `mnc_directory` 只列官方链接，不虚构在招岗。
- 未收录的城市**不猜网址**：只给全国通用渠道 + 自助检索提示（空白比编造好）。
- 夜间自动化只产日报、不改 skill；skill 改动在早晨人工对齐后进行。
